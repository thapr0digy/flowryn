# A new leader session takes over a stale leader lease

- Status: done

Seen 2026-11-03: L8 started in pane wG:p1, the pane of the holder L7, whose Claude a restart had killed before its exit hook ran. L8 stayed read-only until `flowryn leader claim`, because a lease was stale only after `stale_ms` (10 min) of no heartbeat and the check ran only at session start. Older sessions L4 and L5 in the same pane were still open days later.

What changed (no new verb, flag, config key or schema):

- **Same pane** (`leaseState`, src/lease/lease.ts): a session in the holder's Herdr pane sees the lease stale as soon as the holder's recorded process is proven gone (the pid + start + exe check returns false), with no `stale_ms` wait. A pane runs one harness, so a new session there means the old one is gone. An unknown check (ps unreadable, no process recorded) still holds, as does any pane mismatch or a null pane on either side.
- **Re-check on later prompts** (`prepareLeaseRecheck`, src/leader/hooks.ts): a read-only session runs the stale check before each prompt hook (Claude UserPromptSubmit, Pi before_agent_start and agent_start) and claims under the same epoch guard session start uses; its briefing rides that prompt (`brief_pending`). leaseState calls ps only when the holder's heartbeat is older than `stale_ms` or the panes match, so a reader in another pane with a live holder costs a few database reads. A live, silent holder (a sleeping laptop) is still never taken over. A Pi reader that takes over this way fetches its approval key through `hook approval-key`, as after `leader claim`.
- **Dead sessions close**: the holder a stale claim replaces is closed (`ended_at`, reason `process gone`). At session start the new session also closes the other open sessions in its pane whose process is proven gone (`deadPaneSessions`), skipping any that hold a lease. This rides the stale check at session start rather than a new reconciler pass: only a new session in a pane shows the old ones there are gone, and no existing reconciler pass looks at leader sessions.

Scopes: only the session's own scope's lease is checked or claimed, and a session whose login is unconfirmed never claims or closes anything.

Tests: test/unit/lease.test.ts ("a session in the holder's own pane"), and test/integration/leader-stale-takeover.test.ts through the real Claude leader hooks: a new session in the holder's pane claims at start and closes the pane's dead sessions; a reader in another pane stays read-only while the heartbeat is recent; a reader claims on a later prompt once the holder is silent and gone, never while it is silent but alive; a reader in the holder's pane claims on its next prompt at once.
