# `flowryn show --full`

- Status: done

Item and title lines carried tasks-axi's "(truncated, N chars total - use show <task> --full to see complete text)", and `flowryn show <task> --full` failed with "unknown flag --full". The sentinel was tasks-axi's: 0.2.5's `list` cuts a title at 80 characters and a body at 500, and the snapshot stored that cut text, so a queued task dispatched with `--task` also got a cut body. Plain code throughout, no model.

- **Whole text in the snapshot** (`listTasks`, `src/journal/tasks-axi.ts`): after `list`, each task whose title or body ends in the sentinel naming that task (and a total longer than what was kept) is read again with `tasks-axi show <id> --full`, four at a time. A failing `show` fails the read like a failing `list` (the watcher retries; the journal patches from the mutation's JSON). A snapshot written before this has the file's current hash, so the watcher re-reads it once anyway and stores it whole with a `backlog.restored` event, not as a hand edit.
- **`show --full`** (`src/lifecycle/show-text.ts`): without it, `show` cuts as before (titles 120, steer bodies 60, questions 80, a decision's blocks 200, item lines 100, a queued body's first 6 lines at 120 each) and, when it cut anything, ends with `truncated: flowryn show <id> --full for the complete text`, the target you asked for. With it: whole titles, lines and bodies for a queued task, a run (title, plan, steers, questions, items, the latest report's summary), an item, a decision's blocks (its question, why and context print whole anyway, docs/m5-notes.md, "Questions stored whole") and a plan (each phase's body, which the default view leaves out; its hint names `--full`). Divergences and a `worker_report` item were never cut.
- **Item lines**: `items.line` stays the 200-character digest every list reads; migration 15 adds `items.full_line`, the whole sanitized line (at most 4,000 characters) only when the digest cut it (`itemLines`, `src/attention/items.ts`; a line rewritten in place, a PR-ready item's or a usage pause's, rewrites both).
- **Protocol**: this adds no `PROTO` bump, as for `merge --allow-red`: one optional flag on a read. An older CLI never sends it; a newer CLI against an older daemon gets `bad_args` "unknown argument full". It ships in the version main is at (0.13.0, `PROTO` 6).
- **Tests**: `test/unit/tasks-axi.test.ts` (the sentinel's rule; the real tasks-axi cuts and `listTasks` reads whole), `test/unit/watcher.test.ts` (a cut snapshot is restored once, not an edit), `test/unit/show-full.test.ts` (each target kind, cut and whole, and the pointer) and `test/integration/queued.test.ts` (`flowryn show <task> --full` through the CLI and daemon).
