# Workers launch reliably whatever the user's shell prints at startup

- Status: done
- Open: none. `flowryn doctor --contracts --verify-only` passed for Claude 2.1.308 (12/12) and Pi 0.87.1 on this build, 2026-10-22

Workers now start in a pane whose shell runs none of the user's startup files. When a launch still fails, the failure quotes what the pane shows. Everything here is plain code: a fixed shell script, an env entry and a text formatter. No model is used.

## The problem (2026-10-17)

Every Claude launch failed with "the claude process did not appear in pane … within 30000 ms", `flowryn doctor --contracts` included, so `contract_unverified` blocked all dispatch. Herdr's `agent.start` types the harness command into the pane's interactive shell. oh-my-zsh's ".zshrc" asked "[oh-my-zsh] Would you like to update? [Y/n]" and read one key, which took the first character of the typed command: `/Users/…/claude` ran as `Users/…/claude`. Any startup prompt, slow rc file or plugin that eats typeahead does the same. The error said nothing about it.

## What Herdr 0.7.5 offers (spike h08 and lab probes)

Probed in a lab session against Herdr 0.7.5's own schema (`herdr api schema --json`):

- `workspace.create`, `tab.create` and `pane.split` take `cwd` and `env` but no command. `agent.start` takes only `name`, `kind`, `pane_id`, `args` and `timeout_ms`, and needs the pane at an interactive shell prompt: it always types.
- **A pane's shell is the `SHELL` in `workspace.create`'s env.** With `SHELL=/bin/sh` the root pane ran `-sh`; with `SHELL=<a script>` it ran the script. Without one it is the server's (`-zsh` here).
- `layout.apply` takes a pane node with `command` (argv), `cwd` and `env` and starts that process directly, but in a new tab beside the root pane (with `tab_id` it must not name the workspace too), and a pane whose command exits closes at once, leaving nothing to read.
- `pane.read` with source `recent`/`recent_unwrapped` came back empty while a job held the foreground, though `visible` showed the screen. It returns text with the shell at its prompt, which is the failed-launch case below.

## What this change chose

**The launcher names Flowryn's pane shell as the pane's `SHELL`** (`src/lifecycle/pane-shell.ts`, written to `<state_dir>/pane-shell`, 0700, rewritten only when its text changes). The script puts the user's login shell back in `SHELL` (the daemon's `SHELL`, else the account's from `getpwuid`), so the harness and Claude's Bash tool see the real one. It drops `ENV` and `BASH_ENV`, then `exec /bin/sh -i`. A non-login interactive `sh` reads no startup file but `$ENV`, so nothing reads the terminal before Herdr types the launch. `agent.start`, the shell-plus-foreground-job model the reconciler reads (`pane.process_info`'s `shell_pid` against the foreground group), Herdr's agent detection and the typed-length limit (`MAX_TYPED_COMMAND`) all stay as they were.

Why this path and not the others:

- `layout.apply` with the harness argv would start it with no shell at all. The pane's process would then be the harness (`shell_pid` equal to the foreground group), which breaks how the launcher and reconciler find a harness, and Herdr would lose its `agent.start` registration. `layout.apply` with `["/bin/sh", "-i"]` works, but it needs a second tab and a close of the root pane (whose user shell would still run its rc), plus a new allowed method, and its focus behaviour is unproven. Naming `SHELL` costs nothing: it is the same one `workspace.create` call.
- Waiting for the user's shell to settle, or typing a sentinel first, still types into a shell Flowryn does not control.

The environment Flowryn builds reaches the pane and the harness unchanged: the run's variables, the blanked Claude session ids, and `PATH` (the shim directory first, then the daemon's PATH, which the launchd agent sets from the recorded tools and the system directories). One difference from before: whatever the user's rc file *added* on top of that, such as an extra PATH entry, an export, or an alias like `pi` → `pi-signed`, no longer reaches the harness. The Herdr server's own environment still does. The shim now always wins over such an alias. Claude's Bash tool still runs commands in a snapshot of the user's own shell config.

**The harness shim is a symlink** (`ensureHarnessShim`, `<state_dir>/shims/<harness>`, first on PATH). It used to be a script that exec'd the resolved binary. The first live contract run on this build failed "urgent while busy": the urgent cut was deferred with "Herdr reads the worker unknown, not working". Herdr names a pane's agent from its foreground process's argv0 (lab probe 2026-10-22, `pane.get`, `pane.process_info` and `agent explain` on real Claude 2.1.308). Through the script shim argv0 was the binary's own name, `2.1.308`, in zsh and in the pane shell alike, so Herdr saw no agent and read every status "unknown". The interrupt key is refused unless Herdr reads "working", so the cut never ran. Through a symlink the process keeps the typed name `claude`, and Herdr detects it. Main had passed only because the user's `.zshrc` put a `claude` ahead of the shim on PATH, so the shim never ran. The pane shell, which skips that rc file, exposed the bug. The link is replaced atomically (a temporary link renamed over it), and only when it points elsewhere. Main meanwhile taught the script shim to unset an account's `FLOWRYN_UNSET` names (docs/notes/2026-10-22-multiple-ai-provider-u9.md). A symlink runs nothing, so the merge moved that loop into the pane shell, which runs it before Herdr types the harness, so the harness and its tools inherit the unset environment as before.

**A launch failure names the cause.** When the harness process does not appear within `launch_timeout_ms`, the launcher reads the pane's last 40 lines (`recent_unwrapped`, so a secret is redacted whole). Secrets are redacted, control characters and ANSI codes dropped, each line cut to 200 characters, and the last 6 non-empty lines joined with ` | `. They go into the failure: "the claude process did not appear in pane w1:p1 within 30000 ms; the pane's last lines: [oh-my-zsh] Would you like to update? [Y/n] | zsh: no such file or directory: Users/…/claude". A blank pane says "the pane showed nothing", a gone one "its pane is gone", and a failed read says why. The reason is the run's `run.failed` payload, its `failure_needs_you` item and (cut to 150) the parked hold. It is also the contract suite's `launch` step detail, which prints that payload. Only `recent_unwrapped` is read, not the `visible` fallback h08 showed: a soft-wrapped screen line could split a secret past the redactor.

`CONTRACT_REVISIONS` goes up one for both harnesses (Claude 3, Pi 2, after main's accounts change took Claude to 2), because how a worker launches is what the suite's `launch` step proves. Older passes are stale until `flowryn doctor --contracts` passes again on this build. This is the first bump. Five tests had assumed this build is at the baseline: two fixtures (three of the tests) seeded a pass with no revision and now seed it at this build's, and two auto-check tests about rows stored before revisions now pin the baseline through a new `revisions` dependency of `AutoContractChecker` (the gate already took one).

## Tests

- `test/unit/pane-shell.test.ts`: the real script, with every startup file (`.profile`, `.shrc`, `.bashrc`, `.zshrc`, `$ENV`, `$BASH_ENV`, …) set to read one line and report it. The first typed line arrives whole and no rc runs (the assumption that a non-login interactive `/bin/sh` without `ENV` reads none). `SHELL` is restored, a quote in its path included. The 0700 write and the rewrite only on change. The tail's bounds (6 lines of 200), redaction before the cut, control characters, and the blank, gone and unreadable cases.
- `test/unit/pane-shell.test.ts`, the shim: a name typed through the shim starts a process whose args read `claude 30`, not the binary's path (the assumption that Herdr detects the agent from argv0; the old script shim gives `/bin/sleep 30`). An older script shim is replaced, and a correct link left alone.
- `test/integration/pane-shell.test.ts`, against the fake Herdr, which now picks a pane's shell as Herdr 0.7.5 does (`env.SHELL`, else the server's). With `serverShellPrompt` the server shell eats the first typed character. A launch there succeeds in a pane whose `SHELL` is Flowryn's; without the launcher's `SHELL` the same test fails with the run failed. With `startFailure` (no harness, the pane shows an oh-my-zsh prompt, a shell error and a token), the run fails naming those lines, with the token redacted.
- `spikes/herdr/h08-pane-shell.sh` (live, lab session): a ZDOTDIR whose `.zshrc` reads one key, and a stand-in `pi`. In the user's zsh, `agent.start pi` printed `zsh: command not found: i` and no harness started. In a workspace with `SHELL=<pane shell>`, the stand-in came up and printed `SHELL=/bin/zsh`. Verdict confirmed (Herdr 0.7.5).
