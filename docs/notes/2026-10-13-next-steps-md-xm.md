This one covers the rest of the daemon's long-lived external operations: verification steps, no-mistakes, Docker, git network calls, the forge, and the axi tools.

## Design

### The defect every helper shares

The daemon has eight copies of one spawn pattern: `runCommand` (`src/policy/command.ts`: no-mistakes, lsof), `gitRunner` (`src/policy/git.ts`: every git call, network ones included), `runTool` (`src/daemon/daemon.ts`: the launcher's `worktree add`, the build watcher's fetch, local git), `runProc` (`src/daemon/restart.ts`: smoke check, launchctl, plutil), `processRunner` (`src/journal/tasks-axi.ts`), `probeQuota` (`src/sched/quota.ts`), `listLabelled` (`src/reconcile/docker.ts`) and `githubToken`'s `gh auth token` (`src/forge/github.ts`). Each of them:

1. sends SIGKILL to the child's pid only, at its timer;
2. then awaits `Promise.all([stdout.text(), stderr.text(), exited])`.

A descendant that inherited the pipes keeps step 2 waiting after the leader is dead: `git fetch` → `git-remote-https` or `ssh`, a node CLI that forks, a shell wrapper. The timeout does not bound the call, the descendant is orphaned, and nothing records it. Killing with SIGKILL also gives git no chance to run its own signal cleanup (`worktree add` removes its half-made worktree and admin directory on SIGTERM, not on SIGKILL), which is how a `locked: initializing` worktree that `git worktree prune` skips gets left behind. The upkeep build's `runStep` (`src/upkeep/build.ts`) has the same pid-only kill for `bash scripts/build.sh` and `bun install`, whose compilers outlive it.

### Inventory

Deadline, termination owner, what a kill leaves, and how it is recovered, after this change. "Bounded" means `runBounded` (below): its deadline, SIGTERM to the group, grace, SIGKILL to the group, a bounded pipe drain, and the ownership ledger.

### Rule: `runBounded` (`src/runtime/bounded.ts`)

One helper replaces the eight copies; each keeps its own signature and result shape, so no caller changes.

- *Deadline and escalation.* At `timeoutMs` the child's group gets SIGTERM, then after `graceMs` (default 2 s) SIGKILL. The leader is reaped by Bun; once it exits, the pipes get `drainMs` (default 1 s) to close, after which the readers are cancelled. The end-to-end budget of a call is `timeoutMs + graceMs + drainMs` plus up to 1 s confirming the group is gone.
- *Process group.* In the daemon (once `configureOwnedProcesses` has run) every child is its own group leader (`detached: true`), so the kill reaches its descendants. Being detached, it also escapes launchd's job-group kill, which is why the daemon owns its stop (below). Outside the daemon (the CLI, hooks) children stay in the caller's group, so Ctrl-C still reaches them, and the timeout kills the leader with the same SIGTERM → SIGKILL sequence.
- *A normal exit is left alone.* A leader that exits on its own is not followed by a group kill: a tool may leave a process on purpose (`git gc --auto --detach` does, after `setsid`; `no-mistakes` may start its daemon; git may leave a credential helper or fsmonitor, docker its helpers). Only the deadline path, the daemon's stop and recovery signal the group.
- *A finished leader keeps its code.* When the leader exited on its own and a process it started still holds the pipe after `drainMs`, the readers are cancelled and the call returns the leader's code with the output read so far, `lingering` set and a daemon log line naming it; the process is left running. The leader wrote its answer before it exited, so that output is the answer (before this change such a call hung until the holder exited).
- *Unknown, never nothing.* A timed-out call (a leader that did not finish) returns exit code 124 (as `gitWithin` already does), with `timedOut`. Output over `maxOutputBytes` (16 MiB per stream, the rest discarded but drained so the child never blocks) returns code 125 and says so in `stderr`, even when the leader exited 0: a truncated `axi status` or `docker ps` must not parse into "no run" or "no containers". Callers already treat non-zero as a failed read. A caller that never read stderr (`docker ps`, `gh auth token`) still discards it (`stderr: "ignore"`), so neither its size nor a holder of it can change their result.
- *Ownership ledger.* While a daemon child runs, `<state_dir>/owned/<pid>.json` holds `{pid, spawned_at, argv0, label}` (written atomically after spawn, removed once the call settles). It is the exact record of what the daemon owns, kept out of `flowryn.db` because it changes on every call and records no workflow state.
- *Daemon stop.* `stopOwnedProcesses`, called once the listener is closed and the journal has settled or the 12 s shutdown grace has run out, sends SIGTERM to every live group, waits up to 2 s, SIGKILLs what remains and removes the entries of groups confirmed gone; a group that outlives SIGKILL keeps its entry for the next start, which ends the group if its leader is still the recorded one and otherwise drops the entry as `gone` without signalling the members left (see "A descendant that outlives its leader" below). This adds at most 3 s to the stop. A tasks-axi mutation still running when the grace runs out is cut there; its intent is still pending in `flowryn.db` and replays on the next start, as after a crash.
- *Startup recovery.* `recoverOwnedProcesses` runs right after `daemon.started` and before the first reconcile pass, which is where the launch, resume and cancel operations recover (`src/lifecycle/operation-recovery.ts`, `2026-10-13-next-steps-md-rz.md`). That order is deliberate: an operation's relaunch runs `git worktree add` and git calls of its own, and the external commands the last daemon left (a fetch holding ref locks, a hung `worktree add`) are gone before it does. The two never act on the same process: the ledger only names commands `runBounded` spawned, never a worker, which Herdr starts and the operations identify. It reads every entry. A live process at that pid that leads its own group and started within 2 s of `spawned_at` (its start taken from ps `etime`, elapsed time, so the time zone ps and the daemon each read `lstart` in cannot shift it; `bun test` runs in UTC while its ps child prints local time) is the recorded one: its group gets SIGTERM, a grace, SIGKILL (through `terminate`, which re-checks the identity before each signal), and the entry is removed. A pid that is gone or is another process removes the entry and signals nothing. An entry that cannot be read is kept and reported, as is a group that will not die or an entry that cannot be checked (ps fails for it, or the leader is alive but ps cannot read its group and start: exits non-zero, times out or prints what does not parse; the remaining entries are still recovered): all are checked again at the next start, which drops any whose leader has gone by then. A `.json.tmp` (the daemon died between writing an entry and renaming it) is recovered like an entry when it reads; a torn one names nothing and is removed. The lists (`ended`, `gone`, `failed`, `unreadable`, `discarded`) are appended as one `daemon.owned_recovery` event and written to the daemon log. The executable is not part of the match: exec chains (a shebang script reads as `/bin/sh`, the `/usr/bin/git` shim execs the real git) make it unpredictable from `argv`, so start time, pid and group leadership are the identity; a pid reused within the 2 s window by another group leader is the residual risk.
- *Unrelated processes.* Nothing is signalled except a group whose leader the daemon spawned (in memory) or whose leader matches a ledger entry's identity (at startup). No process is found by name or label.

**Files.** New `src/runtime/bounded.ts`; `src/policy/command.ts`, `src/policy/git.ts`, `src/daemon/daemon.ts` (`runTool`, configure, stop, recover), `src/daemon/restart.ts` (`runProc`), `src/journal/tasks-axi.ts`, `src/sched/quota.ts` (`probeQuota` takes a timeout), `src/reconcile/docker.ts` (`listLabelled` takes a timeout), `src/forge/github.ts` (the token, with a timeout parameter, and the body read), `src/upkeep/build.ts` (`runStep`).

**Tests.** Named after the assumption each checks.

- `test/unit/bounded.test.ts` against real processes: a silent child holding the pipes through a grandchild is stopped within `timeoutMs + grace + drain` with code 124 and both processes gone; a child that ignores SIGTERM is SIGKILLed after the grace; a leader that exits 0 (or 3) while a descendant holds stdout returns its own code and the output it wrote within the drain, with `lingering`, and the descendant is left running; a leader that does not finish while a descendant holds stdout is 124; output over the cap is 125; an unrelated process in another group survives; the ledger holds the entry while running and not after; `stopOwnedProcesses` ends a running group; `recoverOwnedProcesses` ends a recorded live group, drops an entry whose pid is gone or belongs to a process started outside the window, keeps an unreadable entry and reports it, recovers a readable `.json.tmp` and removes a torn one, goes on past an entry whose ps fails, and leaves an unrelated process alone.
- `test/unit/external-ops.test.ts`, per fixed operation, with the existing fakes extended: the fake no-mistakes (`test/helpers/harness.ts`) gets a silent mode (`$FLOWRYN_HOME/nm-silent`: it forks a sleeper that holds stdout and waits on it), the fake docker (`test/helpers/fleet-env.ts`) the same (`docker-silent`), the fake forge (`test/helpers/fake-github.ts`) a `stall` mode (no headers, or headers and a body that never ends). `readNmStatus` and `concludeParkedRun`, `listLabelled`, a `gitRunner` fetch over a silent `core.sshCommand`, a `gitRunner` `worktree add` whose `post-checkout` hook hangs (the same `runBounded` call `runTool` makes for the launcher), `processRunner`, `probeQuota`, `tokenSource`'s `gh auth token`, `runProc`, the build `runStep` (a `build.sh` that forks a child and hangs), and both forge stalls each fail within their budget, with their descendants gone, the ledger empty, and an unrelated process (and, for git, the refs and an unrelated worktree) untouched. `listLabelled` with a docker that leaves a helper holding its stdout, and floods and holds stderr, still lists the containers; `gh auth token` with a flooded, held stderr still gives the token. The forge's body stall failed before the fix (a raw `AbortError`, not a `ForgeError`).
- `test/integration/outages.test.ts`: a daemon SIGKILLed while its reconcile pass waits on a silent `docker ps` leaves the fake's sleeper running and its ledger entry in place; the next start ends exactly that group, removes the entry, appends one `daemon.owned_recovery` naming `docker ps`, and leaves an unrelated process running.

**Migration.** None: the ledger is files in the state directory, the event is a new kind.

### Left open

- `lavish-axi poll` (`src/lavish/poller.ts`): long-lived by design, with an owner (the poller), a pid file per gate and a startup sweep; its halt sends SIGTERM only, with no SIGKILL escalation.
- `ps` (`psRunnerAt`, `src/runtime/proc.ts`) has no deadline, and a failing ps reads as "process gone". It is local and does not fork; making its failure unknown changes every liveness reader (the reconciler, `terminate`, the lease), which is its own change.
- `spawnSync` calls with no timeout: the Claude trust check's `git rev-parse` (`src/harness/claude/trust.ts`) and the poller's sweep `ps`; both local and blocking, both to get a `timeout` option.
- Leaf tools with a pid-only timer: `osascript`, `/usr/bin/open`, `<harness> --version`, `herdr session list`, the `[sched] probe`. None forks in practice; they move to `runBounded` when touched.
- The detached `launchctl kickstart -k` of a restart: meant to outlive the daemon; its owner is launchd.
- A descendant that outlives its leader across a daemon force-kill is not recovered: once the leader is gone no identity proves the group is ours.
- Verification's git calls are not counted against the job's `timeout_ms`; each is bounded on its own.
