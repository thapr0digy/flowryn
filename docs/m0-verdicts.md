# M0 verdicts

This is the record for milestone M0 in [`design-v3.html`](design-v3.html) (section 17, "Contract spikes and fixtures before any product code"). Each row is one spike under [`spikes/`](../spikes): the claim it tests, the exact tool version, how it was tested, the verdict, and the evidence. The last sections list every edit made to the design because of these verdicts, plus findings that fall outside the M0 marks.

Run date: 2026-09-23, macOS (Darwin 25.3.0), in the trusted task worktree `/Users/pr0digy/.treehouse/flowryn-81557b/1/flowryn`. The Claude-backed spikes need a checkout Claude Code already trusts (see the README). Verdicts are `confirmed`, `refuted`, `partial` (holds only with a change or a caveat, which the design now states), or `not run`. The Pi spikes ran later the same day, after Pi was installed; see [Pi bridge](#pi-bridge).

Tool versions tested:

| Tool | Version |
|---|---|
| Claude Code | 2.1.281 (Haiku 4.5 for most spikes; Sonnet 5 where auto mode or model judgment matters) |
| Herdr | 0.7.5, protocol 17 |
| tasks-axi | 0.2.5 |

| Pi | 0.87.1 (`/opt/homebrew/bin/pi-signed`, the Pi Launcher build of `@earendil-works/pi-coding-agent`), with every verdict-bearing turn from the offline scripted provider `flowryn-scripted/scripted` |

How to rerun: see [Running the spikes](../README.md#running-the-m0-spikes). The Herdr and Claude spikes ran in an isolated lab session made by Firstmate's `bin/fm-herdr-lab.sh`, never in the default session and never in a pane they did not create. The design's scratch session name `flowryn-contract` was not used. Each Claude session starts from the repo root with `--setting-sources user` plus its own `--settings` file, and keeps its logs and settings in `spikes/.runs/<id>/` (finding 9 explains why).

## Pi bridge

Pi 0.87.1 was installed after the first M0 pass, and all 14 Pi spikes ([`spikes/pi/`](../spikes/pi)) then ran live. Each ran in an isolated Herdr lab session from `fm-herdr-lab.sh` (label `flowryn-m0-pi`) and drove the real Pi TUI in a pane.

No paid or credentialed model produced a verdict. Every turn came from [`spikes/pi/lib/scripted-provider.ts`](../spikes/pi/lib/scripted-provider.ts), a Pi extension that registers the offline model `flowryn-scripted/scripted` with `pi.registerProvider`. The provider plays tool calls, replies, retryable errors, a context overflow and near-full usage from a script embedded in the prompt. The verdicts are therefore reproducible and test Pi's plumbing rather than model judgment.

Each Pi process used a scratch agent dir (`PI_CODING_AGENT_DIR`) and a scratch `--session-dir`. `p11` shows the real `~/.pi/agent/trust.json` was unchanged. The method and harness notes are in [`spikes/pi/NOTES.md`](../spikes/pi/NOTES.md).

## Findings outside the M0 marks

These did not change the design, but M1 and M2 should know them.

1. **Harness panes inherit the Herdr server's environment.** A Herdr server started from inside a Claude Code session passes `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION` and `CLAUDE_CODE_MESSAGING_SOCKET` to every pane. A Claude launched there then runs as a child session ("Transcript saving is off — inherited CLAUDE_COD…"), and it could reach the parent session's messaging socket. The spikes scrub these before provisioning (`lab_scrub_env`). The M2 worker launch should blank or override them on `pane.split`, or check that the Herdr server was started clean.
2. **`agent start … -- <args>` cannot go through the lab helper safely.** `fm-herdr-lab.sh run` appends `--session <lab>` after the arguments, which puts it inside the agent's argument list after `--`. The spikes launch Claude with `pane run` instead. flowrynd will call `agent.start` over the socket, so this only affects shell tooling.
3. **Claude Code 2.1.281 blocks a bare foreground `sleep`** ("Blocked: standalone sleep"), and the model then backgrounds it. Any contract test that needs a long foreground tool call should use something like `perl -e 'sleep N'`.
4. **Auto mode is model-dependent.** On Haiku 4.5 a requested `--permission-mode auto` silently ran as `default`. The approval channel still works there, because ask prompts in default mode too. But `flowryn lead` should check that the first hook's `permission_mode` reads `auto` if it relies on auto.
5. **The asyncRewake wake is framed as an error.** The model sees `Stop hook blocking error from command "Stop": <line>`. The prefix is set by the `@internal` `rewakeMessage` field. The P0 line should read as a fact that stands on its own.
6. **A faster interrupt signal exists.** The transcript at `transcript_path` (given to every hook) records `[Request interrupted by user…]` at once. The reconciler could watch it to clear busy in seconds instead of 10 minutes. This is left for M3.
7. **tasks-axi `done --pr` rewrites the title as read back** (the URL is appended). The backlog watcher's title diff must ignore that, or it will see a hand edit.
8. **A stale tasks-axi lock is never broken automatically.** After a crash, the journal's retries fail until the lock is removed, and the P1 "backlog out of sync" item is the only signal. Its help text should name the lock path.
9. **The external-import dialog is real, and it hit the spikes.** Once this repo gained the `CLAUDE.md` → `@AGENTS.md` pointer, every Claude started in a subdirectory stopped at "Allow external CLAUDE.md file imports?". That is one of the three wedge dialogs in §5. Neither `--add-dir <repo root>` nor `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` avoided it. Approval is stored per project in `~/.claude.json`. Workers start at their worktree root, so an import of the project's own `AGENTS.md` is safe. A project `CLAUDE.md` that imports anything outside the worktree would wedge every fresh worker, so M2's `preTrust` must pre-approve it or refuse the dispatch. The spikes start Claude from the repo root, and use `--setting-sources user` so the worktree's `.claude/settings.local.json` (the supervisor's hooks for this task) never loads in a spike session.
10. **Pi runs as one compiled binary, and extensions need no `node_modules`.** The Pi Launcher build (`/opt/homebrew/bin/pi-signed`) resolves `@earendil-works/pi-coding-agent`, `@earendil-works/pi-ai` and `typebox` as built-in modules for `-e` extensions. The Flowryn extension can ship as one `.ts` file.
11. **A long launch command is cut off when typed into a pane.** A Pi command line of about 1.4 KB was truncated in the pane shell. The spikes write each launch to a script and run that. flowrynd will use `agent.start` over the socket, so only shell tooling is affected.
12. **Every Flowryn-launched Pi loads the user's environment.** That means `<agent-dir>/extensions` (for example Herdr's state extension), `~/.agents/skills`, and the `AGENTS.md` files above the cwd. The M2 worker launch should decide deliberately on `--no-extensions` (which keeps `-e`), `--no-skills` and `--no-context-files`.
13. **An abort can race a queued message.** When `ctx.abort()` ran in the same tick as the queueing, the queued user follow-up survived the abort and was delivered after the next prompt. When the abort ran seconds later, it moved into the composer. Either way the delivery ticket must treat a steer queued before an interrupt as not presented, and dedup by id.
14. **A bad busy send is visible to you.** A busy `sendUserMessage` without `deliverAs` shows a red extension error in your Pi TUI. The bridge must always pass `deliverAs`.
